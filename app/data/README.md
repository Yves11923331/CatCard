# app/data · 周易经部权威数据

本目录只有一件东西：`zhouyi.json` —— 《周易》经部（64 卦 / 386 爻）的结构化数据。
它是**生成物**，不是手写文件。

```
材料（只读，绝不改）            生成                           编译进包
周易古经占_参考.md        →   app/data/zhouyi.json        →   app/www/js/builtin-zhouyi.js
app/decks/易经牌组.json   ↗   （权威数据）                    （= 上面这份的内联副本）
      （只用作交叉校验）                                            global.MoKaBuiltinZhouyi
```

| 动作 | 命令 |
| --- | --- |
| 生成 | `python3 app/tools/gen_zhouyi.py` |
| 校验是不是最新（不写文件，不一致 exit 1 并指出第一处不同） | `python3 app/tools/gen_zhouyi.py --check` |
| 指定材料 / 牌组 / 输出（测试用） | `--src` `--deck` `--json-out` `--js-out` |

- **解析逻辑只在 `app/tools/gen_zhouyi.py` 里**，材料丢了直接报错退出，不会拿旧数据兜底。
- 自检是**硬断言**：任何一条不过就 exit 1，并且**一个文件都不写**。
- `www/js/builtin-zhouyi.js` 由 `www/index.html` 所在的那层按需 `<script src>` 加载，
  `aapt -A app/www` 会把整个 www 打进 assets，不需要改构建脚本。

## zhouyi.json 结构

```jsonc
{
  "format": "moka-zhouyi/1",
  "meta": { ... },              // 术语速查用：体例 / 兆辞表 / 帛书卦名对照 / 索引 / 参考来源
  "hexagrams": [ /* 64 条，下标 = 通行本卦序 - 1 */ ]
}
```

### meta

| 字段 | 内容 |
| --- | --- |
| `tiLi` | `{heading, raw, items[]}` —— 体例。`raw` 是原文（含 〔异文〕〔异解〕〔待考〕 三个符号的定义），`items` 是逐条 `{label, text}` |
| `terms` | `{heading, raw, rows[], note}` —— 核心术语·兆辞一览。`rows` = `{term, kaoju, old}`（考据义优先 / 儒家旧注另说），`note` 是表下的「说明」 |
| `guNameTable` | `{heading, raw, caption, rows[]}` —— 帛书卦名对照。`rows` = `{no, name, boshu}`，`boshu` 里可能带 〔待考〕 |
| `index` | `{heading, raw, rows[]}` —— 六十四卦索引。`rows` = `{no, glyph, name, py}` |
| `sources` | `{heading, raw, items[], note}` —— 主要参考（考据来源） |

每个小节的 `raw` 都是材料原文整块（markdown 原样），做「术语速查」时直接展示即可。

### hexagrams[i]

| 字段 | 说明 |
| --- | --- |
| `no` | 1~64，通行本卦序（与牌组卡序一一对应） |
| `glyph` | 卦画字符 ䷀…䷿（`chr(0x4DC0 + no - 1)`） |
| `name` | 卦名：乾 / 坤 / 屯 … |
| `py` | 拼音，**可能含空格**：`tóng rén`、`xiǎo xù`、`dà zhuàng` |
| `alias` | 异名，只有 33 遁 → `遯`；其余为空串 |
| `gloss` | 【卦名】那段考释**正文**（不含 `**【卦名】**` 标记，界面自己加小标题） |
| `insp` | 启发**那句**（不含 `启发：` 前缀） |
| `gua` | 卦辞原文 |
| `guaTr` | 卦辞白话直译 |
| `guaNotes[]` | 卦辞的 〔…〕 标注，**单独放、没拼进译文**；只有乾、坤各 1 条，其余为 `[]` |
| `yaos[]` | 爻，乾/坤各 7 条（含用九/用六），其余各 6 条，合计 386 |

### yaos[j]

| 字段 | 说明 |
| --- | --- |
| `label` | 初九 / 九二 / … / 上六 / 用九 / 用六 |
| `text` | 爻辞原文 |
| `tr` | 白话直译 |
| `note` | 〔异文〕〔异解〕〔待考〕 标注，没有就空串 `""`（**不拼进 `tr`**） |
| `special` | 只有 用九 / 用六 为 `true`，其余 `false` |

前 6 条 `yaos` 恒为六爻本体（骰子 1~6 → `yaos[n-1]`），用九/用六排在最后，
所以消费方 `filter(y => !y.special)` 取六爻、`filter(y => y.special)` 取用爻即可。

## 自检清单（都在 gen_zhouyi.py 里，全过才写文件）

1. **卦画 ↔ 卦序**：`glyph == chr(0x4DC0 + no - 1)`。
2. **牌组交叉校验（与卦名字面无关）**：把 `app/decks/易经牌组.json` 每张卡 `art` 里同 y 的线解出来
   （一条通栏 = 阳、断开两段 = 阴），得到自下而上的六位阴阳串，与脚本里硬编码的
   「通行本卦序 → 上下卦」表（`KINGWEN` + `TRIGRAMS`）逐位比对，64/64 全对。
3. **爻题 ↔ 上下卦**：由 `KINGWEN` 推出该卦应有的爻题序列（初九/六二/…），与实际爻题逐条一致。
4. **防漏条**：卦 64、爻 386、乾坤各 7、其余各 6、`special` 恰 2 条；
   材料里 `**` 开头的条目数 == 64(卦名) + 64(卦辞) + 386(爻辞) = **514**。
5. **标注一个不丢**：卦段落里 `〔异文〕〔异解〕〔待考〕` 的出现次数，与数据 `guaNotes` + `note` 里的一致
   （材料：卦辞标注 2 条、爻辞标注 8 条）；整份输出里的总数 ≥ 材料里的总数。
6. **原文可回溯**：卦名 / 考释 / 启发 / 卦辞 / 爻辞原文 / 标注，都能在材料里逐字找到。
7. **三方对齐**：正文标题 ↔ 索引表 ↔ 帛书对照表（卦名、拼音、卦画一致）。
8. **材料缺失**：材料或牌组文件不在 → 直接 exit 1，绝不静默用旧数据重建。

> 负向对照（改错一处看断言会不会红）实测过：改坏牌组卦画一处、删一条爻辞、
> 改错一个卦画字符、把 `KINGWEN` 表改一位、把脚本里的 note 丢掉（变异测试），
> 五种都 exit 1 且不写任何文件。详见交接回报。
