## 0. 谁是谁（改东西只改这些）

| 文件 | 角色 | 能不能手改 |
|---|---|---|
| `app/decks/<牌组名>.json` | ★ **唯一真源**：这副牌叫什么、有哪些卡、符号、牌背 | **只改这里** |
| `app/tools/内置牌组.py` | 工具：`清单 / 校验 / 生成 / 新增 / 下架 / 上架 / 删除` | 改流程本身时才动 |
| `app/www/js/builtin-decks.js` | **生成物**（注册表），进包、排在 `data.js` **前面**加载 | ✗ 别手改，会被覆盖 |
| `app/www/js/data.js` | 只做「注册表 → 牌组」+ 老装机迁移 | 加迁移/新机制才动 |
| `app/test/走查-内置牌组.js` | 钉住这条链（含「忘了生成」守卫） | 加断言时动 |

数据流：

```
app/decks/*.json  ──生成──▶  app/www/js/builtin-decks.js  ──加载──▶  data.js  ──▶  界面
        ▲                                                                    │
        └──────────────── 走查 + 构建前检查（不一致就红）────────────────────┘
```

> 为什么要把注册表**生成**成 JS 而不是让 App 读 JSON：`build_catcard.py` 用 `aapt package -A www`
> 打包，**只有 `www/` 下的文件进 APK**，`app/decks/*.json` 真机读不到。

## 1b. 下架 / 删除一副内置牌组（三种动作，别搞混）

| 你想要的效果 | 用哪条 | 工程里的文件 | 老装机上已有的那副 |
|---|---|---|---|
| **只是这个包先不带它**（以后还要） | `下架 <key>` | 全留着，只在 `不打包.txt` 加一行 | 原样不动 |
| **整副不要了** | `删除 <key>` → `删除 <key> --确认` | JSON / 专属图片目录 / 生成器一起删（★ **不留备份**） | **原样不动** |
| 把手机上的那副也清掉 | —— | —— | 只能让用户自己在「牌库」里删 |

⚠ **删除动不了老装机**：牌组一旦装到手机上，它就是用户的牌组（§4 红线 2）。
注册表里没有它 = 新装机不再建、以后也不再有内容同步；**但用户设备上那副一直留着**。
这不是 bug，是这条流程的地基 —— 所以删完要主动跟用户说：要清自己去牌库删。

### 删除：两步走（不可逆，先看清单）

```bash
cd app

# ① 先看清单（dry-run —— 一个文件都不动）
python3 tools/内置牌组.py 删除 <key>            # 例：删除 gendef

# ② 清单确认无误，再真删
python3 tools/内置牌组.py 删除 <key> --确认
```

dry-run 会把影响面分八段打出来，其中这几段要分清楚谁做：

| 段 | 谁做 | 说明 |
|---|---|---|
| ① 会自动删掉的文件 | 工具 | `decks/<牌组>.json`、`decks/faces-<key>/`（源图目录）、**强证据**的生成器脚本、`不打包.txt` 里那一行 |
| ② 会自动重做 | 工具 | 跑「生成」重写 `builtin-decks.js` |
| ③ ❌ 代码里按这个 key 找牌组 | **人** | 例：周易桌 `builtinKey === 'gua64'` —— 不改，功能就静静坏掉 |
| ④ ⚠ 这副牌专属的东西 | **人** | 专属牌背模板（`library.js` 的 `BACK_TPL` ＋ `ui.js` 的 `BACK_TPL_INNER` 与绘制函数 ＋ `v3.css` 规则）、专属样式类 |
| ⑤⑥⑦ 代码/样式、走查、文档里提到它的地方 | **人** | 逐条过一遍 |
| ⑧ 老装机 | **不用做** | 一个字节都不碰 |

**生成器脚本的判定分强弱**（脚本删了就没了）：
文件名含 key、或内容里就是 `key: '<key>'` = 强证据 → 自动删；
只是注释里提到牌组名 = 弱证据 → **只列出来交人工**
（踩过：`gen_zhouyi.py` 里提了一句「易经牌组」，差点被当成 gua64 的生成器一起删掉）。
内容里还写着**别的牌组 key** 的（疑似共用）也一律不自动删。

删完照这四步收尾（和 §1 的「新增」对称）：

1. 清人工项 —— 上面 ③④⑤⑥⑦
2. `python3 tools/内置牌组.py 校验` —— 三条「删除遗留」守卫要清到全绿（见下）
3. `cd test && node 走查-内置牌组.js`（再跑另两套；**只跑源码**）
4. `python3 build_catcard.py` 构建交付

### 三条「删除遗留」守卫（工具 `校验` ＋ 走查第 7 组）

判据一律是「`decks/*.json` 里还有没有它」：**下架不红，整副删掉才红**。

| 红灯 | 意思 |
|---|---|
| `BACK_TPL 里的内置模板「x」没有任何 decks/*.json 声明它` | 删了牌组却没清它的牌背模板（`library.js` / `ui.js` / `v3.css` 三处） |
| `代码里按 builtinKey === 'x' 找牌组，但 decks/ 里已经没有这个 key` | 硬引用没改（周易桌那种） |
| `这一行排除了一个不存在的 key「x」` | `不打包.txt` 里留了死行（牌组删了那行就该删） |

## 2. 一份牌组 JSON 长什么样

```json
{
  "format": 1,
  "key": "deepsea",                       // 注册表里的稳定标识（小写英文，唯一）
  "name": "深海牌组",                      // 界面上显示的名字（唯一）
  "oldNames": ["深海 · 试作"],             // 早期版本用过的名字：老装机一次性改名（id 不变）
  "order": 30,                            // 内置牌组之间的先后，越小越靠前（唯一）
  "onTable": true,                        // 新装机默认上占卜桌
  "addIfMissing": true,                   // 老装机上缺了这副牌，要不要自动补上（见下）
  "symbols": "none",                      // star / psyche / none：符号从哪张表来
  "back": { "template": null, "color": "#8a7a3a" },   // template 必须已在 library.js 的 BACK_TPL
  "note": "给人看的说明，不进包",
  "cards": [
    { "name": "潮声", "keyword": "倾听", "symbol": null, "sym": null,
      "faceText": "一句话牌面", "meaning": "一段牌义", "color": 0 }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `key` | 注册表键。代码里要找这副牌就按 key（`builtin-decks.js` → `BUILTIN_BY_KEY`） |
| `order` | 内置牌组之间的排序（现在 星语 10 / Psyche+ 30 / Aegis 40 / 六十四卦 50 / 英雄之旅 60）。**只影响内置这几副的相对位置** |
| `onTable` | 新装机（第一次打开）要不要默认上占卜桌 |
| `addIfMissing` | **老装机**上缺了这副牌要不要自动补。**默认那副写 `false`**（用户自己删了就说明他不要，别每次进 App 又塞回来）；**后来补的那副写 `true`**（§54：老装机缺卢恩要补上） |
| `symbols` | `star`→`SYM_PATH`；`psyche`→`PSYCHE_PATH`；`none`→所有卡的 `sym` 留 `null` |
| `sym` | 符号 id（**不是文件、不是字形**）。`symbolImg` 由代码现算成 `assets/sym/<id>.svg`，包里**没有**这个文件 |
| `symbol` | 老的字形字段（兼容老数据/文字兜底），界面上不印 |
| `color` | 调色板序号 `0..7`（`data.js` 的 `PALETTE`），不是色值 |

**卡片字段白名单**在 `data.js` 的 `withCardStyle` 那一行 —— 给卡加字段**必须同时加进那一行**，
否则会像 `id`（抽不出牌）、`symbolImg`（看不见符号）那样被悄悄丢掉。

## 3. 符号从哪来

- 符号是 **ui.js 里的内联 SVG 矢量路径**（`SYM_PATH` 星语 12 个 / `PSYCHE_PATH` Psyche+ 37 个），
  合计 36 = 走查里的 `UI._symCount`。
- **不许**落图片文件、**不许**用 mask、**不许**引外部文件；`www/assets/sym/` 目录必须**不存在**
  （走查里有一条专门钉这个）。`assets/sym/<id>.svg` 只是 id 载体。
- 要一个**新符号**：在 ui.js 对应的表里加一条内联 path（id 要 ASCII），
  然后走查里那两条「符号总数 / 顺序」断言会跟着变，一起改。

## 4. 迁移红线（§54 换来的，别再犯）

1. **判据只落在「这是不是内置的那份东西」**（名字 / 卡名），绝不落在「数据长什么样」。
   早期按「有没有符号图」判 → 把用户自己的两副牌（崩铁 18 + 精分 58）全盖满了 sowilo。
2. **绝不改用户自己的牌组**：改名只改内置那副（就地改、`id` 不变）；补符号只补认错的；
   补牌背只补「从没设过图 / 没挑过模板」的。
3. `addIfMissing: false` 的牌组，用户删了**不塞回来**。
4. 读不到 ≠ 东西没了：任何「读失败」的路径都不许把引用写成 `null`。
5. 新装机的 seed 顺序 = 注册表 `order`；老装机的迁移顺序在 `data.js` 的 `ensureBuiltinDecks()`：
   改名 → 补缺（按 `addIfMissing`，补上的按 `onTable` 上桌）→ 清假符号 → 补符号 → 补牌背 → 排序 → 有改动才落盘。

## 10. 后加的几条规矩（2026-09-20 晚 · 构建 16）

- **`seed` 字段**：`seed: true` = 新装机就建这副；`seed: false` = 只作"身份表/遗留兼容"，**新装机不建它**
  （星语牌组就是 `seed: false`——用户说它是试用的；但它的 12 个卡名留着，老装机那副的星形符号才不会被当成假符号清掉）。
  与 `addIfMissing`（老装机缺了补不补）是两件事，别混。
- **`不打包.txt`**：`app/decks/` 下可能同时有**别的会话**在做的牌组。把它的 `key` 写进 `app/decks/不打包.txt`，
  它就**不进注册表、不进包**（本包的生成/校验都会提示"按不打包.txt 排除"）；JSON 一个字都不动。
  那边要进包时，把那一行删掉再跑 `生成` 即可。
- **内置牌背归属**：模板列表用的是 `D.deckOwnsBack(deck, tplId)`——**谁的注册表里声明了这个模板，只有那副（及其克隆/改名）看得见**。
内置模板现在有三个：`psyche`（划杠 Ⱥ）、`guax`（三爻 ☰）、`aegis`（盾印）。**再加时不用改判定逻辑**
- **牌面排版（长牌名）**：牌面一行只放得下 **4 个字**（可用宽 62.2% ÷ 名字字号 14.4%）。
  超过 4 字的**一律按字数缩字号**（5 字 ×0.80、6 字 ×0.67），**不折行、不拆字**；4 字以内不动。
  → 所以内置牌组的**牌名尽量控制在 4 字以内**，长了会自动变小。
- **牌面句（`faceText`）**：它的去处是**当牌义的第一段（索引）**，不是单独印在牌面上。
  判断标准是"帮助认知还是阻碍认知"——跟正文重复的直接写 `null` 删掉（`faceText` 现在允许为空）。

## 11. 改了内置牌组的内容，怎么让**老装机**看到（`retiredNames` + 内容同步）

**背景**：内置牌组是"装机时建一次"的。`ensureBuiltinDecks()` 只负责"缺了补一副"，
所以**后面改了内容，老装机的手机上永远看不到**（2026-09-20 用户报"拆出来的三张没有呀"就是这个）。
现在 `data.js: syncBuiltinCards()` 每次启动对**名字等于内置那副**的牌组做两件事：

| 字段 | 作用 |
|---|---|
| `retiredNames: ["旧卡名", …]` | **下线的旧内置卡**：名字命中就从这副牌里删掉（涵容 → β元素/α功能/α元素 时用的就是它） |
| （无需字段） | **补齐**：注册表里有、这副牌里没有的内置卡 → 追加到末尾 |

四条红线（走查 3c5 组守着）：
1. **用户改过的卡一个字都不覆盖**——已有的卡只按名字比对，命中就跳过，绝不重写内容；
2. **用户自己的牌组一概不碰**（哪怕他自己的牌组里也有一张叫「涵容」的）；
3. **只认真名**：牌组被用户改过名字/克隆出去的，`name` 对不上就不动；
4. **幂等**：反复启动不会重复追加。

> 给内置牌组"改名"仍然走 `oldNames`（一次性改牌组名）；**给内置牌组"换卡"走 `retiredNames` + 补齐**。别混。

## 12. 插画牌组：牌面图**外置**，不许把 base64 内嵌进注册表（2026-10-08 立）

**为什么**：构建 226 拿 52 张 PNG 原样内嵌（`image` 写 data URL），注册表
`builtin-decks.js` **1.27 MB → 9.20 MB**、APK 2.39 → 8.44 MB，随后崩溃回退（构建 227）。
当时留的"药方"是压 WebP —— **那会掉清晰度**。构建 229 换了范式：
**牌面图当静态资源，注册表里只写一条相对路径**（38 张图的路径合计 1296 字符）。

| 环节 | 怎么写 |
|---|---|
| 源图 | `decks/<key>/faces/<slug>.<ext>`（工程内，**不进包**） |
| 进包资源 | `www/assets/deckimg/<key>/<slug>.<ext>` —— **原字节**搬过去（`shutil.copy2`），不重编码 |
| 卡的 `image` | 写 `assets/deckimg/<key>/<slug>.<ext>`（**相对路径**，不是 data URL） |

**运行时为什么不用改代码**（四处天然成立 —— 别再去动它们）：
- `ui.js` 的牌面就是 `background-image:url(…)`，相对路径按文档解析 —— 与 `assets/sym/`、`assets/fonts/` 同一先例；
- `buildMeta()` 只搬 `data:` 开头的值 → 路径原样进 meta（40 字节），**不占配额、不进 IDB、不进兜底库**；
- `hydrateImages()` 只认 `idb:` / `ls:`，不碰它；`BUNDLED_IMGS` 也收不着（它不是 data:）；
- `io.js` **已经接好**（`DECK_ASSET_PREFIX`）：导出不进 zip、manifest 原样写路径；导入原样还原；
  这条通路上唯一的可测点是 `makeZipPut_`（走查钩子）。

**新增一副插画牌组** = §1 的六步，外加这几条：
1. 图片原字节放进 `decks/<key>/faces/`；
2. 写生成器（`copy2` 到 `www/assets/deckimg/<key>/`，`image` 只写路径；带 `--check` 保证幂等）。
   ★ 2026-10-12 起 `tools/` 里**没有外置资源型的生成器样板**了（雷诺曼那支随退役彻底删掉，用户不再加回来）——
   要写就照 `io.js` 的 `DECK_ASSET_PREFIX` 注释 + 本节，别去找不存在的文件；
3. **牌背**：走 `decks/<key>/back.svg`（`back.template` 要么在 `library.js` 的 `BACK_TPL` 里，要么配 `back.svg`）。
   外置牌背就在 SVG 里写 `<image href="assets/deckimg/<key>/_back.png"/>`（另给 `<rect>` 底色兜底）；
4. **纯插画**（不叠字）加 `decks/<key>/style.css`：
   `.is-fc-<key> .fc-name, .is-fc-<key> .fc-keyword { display: none; }`

**体积红线**：进包资源涨多少包体就涨多少（原图代价，不是浪费）；
**注册表不许涨**。`生成` 完看一眼 `ls -la www/js/builtin-decks.js` —— **超过 3 MB 就是在内嵌**。

**验证**：`node test/验证-外置资源图.js [assets目录] [deckKey]`。端到端盯住六件事：
注册表是路径 / 磁盘逐字节等于源图 / `faceHTML` 吐的就是那条路径 / 落盘原样保留 /
导出 `images/` 零文件 / 导入原样还原。牌组删掉后它会**自动跳过**，不会变红灯。
